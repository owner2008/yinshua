# 8088 会员接口临时保护（2026-09-23）

## 原因与现状

- 阿里云服务器公网 `:8088` 运行独立 H5，**不是** 80/443 的 WordPress 正式官网。旧 H5 发布包会使用固定的开发模拟身份，旧 API 也接受这类身份；不同访客可能进入同一测试会员会话。
- 已在 `:8088` 的 Nginx 代理临时拒绝 `/api/auth/wx-login`、`/api/auth/bind-mobile` 和 `/api/member/`。因此该入口的会员登录、资料、地址及历史报价暂不可用；首页、产品目录和正式 WordPress 官网仍可访问。
- 2026-09-24 已发布认证修复版 API 和取消自动模拟登录的 H5。H5 当前明确显示会员登录暂未开放；真实微信登录参数与入口仍未完成。不要因为前后端安全包已发布就移除代理限制。
- 对共享测试身份做了只读计数检查：账号存在，但目前没有会员档案、地址或报价。未查看个人字段；这不能证明历史上没有其他访问。

## 已完成的保护与验证

- 现行代理配置从服务器原文件同步并校验后编辑，保存于 `deploy/nas/nginx-live-20260923.conf`；原配置备份在服务器 `/root/nginx-8088-before-safeguard-20260923.conf`，候选文件在 `/root/nginx-8088-safeguard-candidate-20260923.conf`。
- 实际代理挂载路径为 `/opt/yinshua/current/nginx.conf`。更新前后均核对文件内容；Nginx 在同一 Podman 网络及运行容器内通过语法检查，随后平滑重载，未重启数据库、API 或 WordPress。
- 公网复核：`:8088/` 与 `/api/catalog/categories` 返回 200；受保护的登录、手机号绑定、会员接口返回 403；正式 HTTPS 官网返回 200。第一次重载因 Podman 内部 DNS 临时解析失败未生效，受控重试后成功；再次验证才认定保护生效。
- 本地源码已将模拟登录改为默认禁用（仅非生产环境显式开关可启用）、旧模拟 token 默认拒绝、手机号绑定改为当前会员授权；H5 取消自动模拟登录和未登录资料表单。本机 API 类型检查、38 个单元测试、9 个独立库集成测试及 H5 构建通过。API 与 H5 安全修复均已于 2026-09-24 发布。

## 2026-09-24 候选 API 验收（发布前记录）

- 服务器上涉及认证修复的 6 个旧源码文件与本地修复前提交逐项一致。已将本地修复后 API 编译结果存放在服务器 `/opt/yinshua/current/api/dist-auth-20260924`，原运行中的 `dist` 未覆盖；传输包 SHA-256 为 `b3e5c0e70cf2da51c2a2b85f0f7b845c9eef38bb6a573dc4407ebe4c50167256`。
- 在现有 API 容器内部临时以 `PORT=3001`、`NODE_ENV=production` 启动候选进程，未通过公网代理。产品分类返回 200，模拟微信登录、无 token 绑定手机号、无 token 访问会员地址及默认管理员凭据登录均返回 401。候选进程已按精确进程命令校验后停止，未切换线上流量。
- 验收期间公网产品目录接口曾有一次 500；旧 API 日志显示当时无法连接 `qddflc-db:3306`。随后旧 API、候选 API 同一路由均返回 200，公网目录连续 5 次返回 200，WordPress HTTPS 也返回 200。数据库容器未重启、无 OOM，连续 5 次容器内 DNS 查询正常；原因尚未定位。**在数据库链路稳定及可回退的部署方案确认前，不切换流量。**
- 进一步复核发现原 API 容器的 DNS 同时含 Podman `10.89.0.1` 和阿里云 `100.100.2.136/138`。50 次系统解析中，短名 `qddflc-db` 有 2 次 `ENOTFOUND`、FQDN 有 7 次；独立询问 Podman DNS 50 次全成功，询问两台阿里云 DNS 各 12 次均找不到该内部名称。临时容器仅配置 `10.89.0.1` 后，内部名称连续 100 次解析成功，外部微信域名也可解析。数据库连接峰值 3/20，无连接数超限错误。证据强烈指向混合 DNS 导致偶发 500；发布配置已准备给 API 和 8088 代理只使用 Podman DNS，尚未生效。
- 线上容器重启仍会执行原启动链的 `prisma:push`/可能的 seed；候选构建本身不执行这些操作，但尚未取代启动配置。不要误把候选文件存在视作发布完成。

## 2026-09-24 正式发布与验证

- 在两份 root 专用数据库快照和原 Compose 备份就位后，发布安全 API 编译包与补 OpenSSL 的运行镜像。正式 API 启动命令现为 `node dist-auth-20260924/src/main.js`，不再在启动时安装依赖、推表、播种或构建；旧 `api/dist` 保留供紧急回退。
- API 和 8088 代理均只使用 Podman DNS `10.89.0.1`。服务器 `podman-compose` 1.0.6 的 `--force-recreate` 曾意外停启旧容器且未应用新配置，造成短暂 502；按依赖顺序精确删除代理/API，再用已校验单份配置创建后修复。数据库也曾跟随重启，API 有一次启动期 `P1001`，随后两轮合计 70 次产品请求均为 200，未见持续错误。
- MySQL 应用/root 密码及管理员、会员签名密钥已轮换；服务器正式 Compose 和运行容器一致且仅 root 可读。代理继续拒绝三个会员入口（403）；直接访问新 API 时，模拟身份登录、无 token 绑定手机号及会员地址均返回 401。8088 首页/目录与 WordPress 官网返回 200。运维和回退细节见 `deploy/aliyun/README.md`。
- H5 新构建会忽略并删除旧 `yinshua_member_session`，未登录时显示“会员登录暂未开放”。完整线上静态目录已备份；发布只增加新 JS 并原子切换 `index.html`，后台目录和旧 JS 均保留。新版入口与 JS、后台、会员代理拦截、连续 20 次目录接口及 WordPress 均通过 HTTP 验收；本轮浏览器连接失败，页面视觉验收尚未完成。

## 恢复会员入口前

1. 明确真实会员登录方式并配置正式微信参数；为 H5 提供真实登录入口，不能再使用固定开发身份。
2. 为 H5 实现正式微信登录入口并配置微信参数，验证真实登录和本人资料访问。新 API 的模拟登录与无 token 访问已在线上直接验证为 401；当前 H5 只有未开放提示，真实登录尚未端到端验证。
3. 当前 API 启动链已安全化；后续重新部署仍须先备份并按依赖顺序重建，避免 `podman-compose --force-recreate` 停启旧容器。详见 `deploy/aliyun/README.md`。
4. 真实登录及 H5 发布验收完成后，才从 8088 配置移除三个临时拦截并平滑重载，重新验证公开页面、产品、登录和会员接口。当前配置使用 `qddflc-api.dns.podman`，重载前仍需执行 `nginx -t`。

不应通过恢复旧代理配置来提前开放会员接口。WordPress 官网与此 8088 保护互相独立。
