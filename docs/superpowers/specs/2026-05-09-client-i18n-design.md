# 前台中英文多语言设计方案

## 背景

项目当前已经完成 PC 官网、H5 首页与子页面、会员中心、历史页、报价页和后台管理功能。用户要求新增多语言能力，首期仅支持中文与英文，并且限定在前台显示内容，后台不需要多语言管理。

## 目标

- 前台支持中文和英文切换。
- 后台保持现有中文管理界面，不新增语言切换入口。
- 不修改数据库结构，不要求后台维护英文内容。
- 现有前台页面、H5 页面、会员中心和历史页都纳入多语言显示范围。
- 语言选择在刷新页面后保持。
- 没有翻译映射的数据保留原始中文，避免页面出现空白。

## 非目标

- 不做后台管理系统国际化。
- 不做数据库字段级多语言。
- 不接入自动翻译服务。
- 不调整现有业务接口契约。
- 不改变报价、会员、历史记录等业务逻辑。

## 推荐方案

采用前端轻量 i18n 字典方案。

前端新增一个语言上下文，提供当前语言、切换语言和翻译函数。静态页面文案通过翻译 key 获取。接口返回的产品、分类、材质、工艺等中文数据通过前端映射表翻译；映射不存在时回退到原始文本。

相比引入完整 i18n 框架，这个方案改动更小，部署风险更低，也符合“只做前台显示内容”的范围。后续如果需要增加更多语言，可以继续扩展字典和映射表。

## 架构

### I18nProvider

新增前台语言 Provider，挂在 `apps/client/src/App.tsx` 的前台应用根部。它负责：

- 读取 `localStorage` 中保存的语言。
- 提供默认语言 `zh-CN`。
- 暴露 `setLocale` 切换语言。
- 暴露 `t(key, vars?)` 获取静态翻译。
- 暴露文本映射工具，用于翻译接口返回的中文标签。

### 语言字典

新增中文和英文字典，首期包含：

- 导航、Footer、CTA。
- 首页所有模块标题、说明、按钮和卡片文案。
- 产品中心、产品详情页文案。
- 报价页表单、步骤、费用说明、校验提示和结果文案。
- 联系我们页面文案。
- 会员中心和历史页文案。
- H5 顶部、底部导航和页面标题。

中文字典作为现有内容的规范来源，英文字典为对应翻译。翻译 key 使用语义化命名，例如 `nav.products`、`home.hero.title`、`quote.form.submit`。

### 远程数据翻译

接口数据不改结构。前端建立中文文本到英文文本的映射表，覆盖以下类型：

- 产品分类名称。
- 产品名称。
- 材质名称。
- 工艺名称。
- 行业名称。
- 常见规格、卖点和标签。
- 公司信息中的英文展示名称、地址等。

映射工具接收原始文本并返回当前语言下的展示文本。如果当前语言是中文，直接返回原文。如果当前语言是英文且存在映射，返回英文；否则返回原文。

### 语言切换入口

PC 端在右上角导航区域增加轻量语言切换入口，显示 `中文 / EN` 或当前语言按钮。它需要保持现有高端企业官网风格，不影响“会员中心”和主 CTA 的层级。

H5 端在顶部区域加入小型语言切换按钮，尺寸紧凑，避免挤占主操作按钮。底部导航文案也跟随语言切换。

## 页面覆盖

### 首页

覆盖 PC 首页与 H5 首页的所有显示文案，包括 Hero、优势、产品、报价引导、应用行业、材质工艺、案例、品质保障、合作流程、客户评价和底部 CTA。

### 产品页面

产品中心、产品详情和 H5 产品子页面需要支持：

- 页面标题和筛选文案翻译。
- 产品分类、产品名称、描述、规格、应用场景翻译。
- 按钮、空状态、加载状态翻译。

### 报价页面

报价页需要支持：

- 基础报价参数。
- 工艺选择。
- 费用拆分与结果文案。
- 表单字段、选项、按钮、提示语。
- H5 与 PC 同步。

### 联系我们

联系方式、公司简介、服务承诺、地图或地址卡片文案进行翻译。电话、手机号等数字内容保持原样。

### 会员中心与历史页

保留现有功能和入口，只翻译显示层：

- 页面标题。
- 卡片标题。
- 字段标签。
- 按钮和状态。
- 空状态和错误提示。

## 错误处理与回退

- 语言值异常时回退到 `zh-CN`。
- 翻译 key 缺失时回退显示 key，便于开发发现问题。
- 远程数据翻译缺失时回退原文，保证页面可读。
- `localStorage` 不可用时使用默认语言，不阻断页面渲染。

## 测试与验证

实现时需要至少执行：

- TypeScript 类型检查。
- 前台构建。
- PC 首页、产品页、报价页、联系页、会员中心、历史页手动切换验证。
- H5 首页和子页面切换验证。
- 刷新页面后语言保持验证。

## 后续扩展

如果未来需要增加日语、韩语或俄语，可以在现有字典和映射表上扩展，不需要重做结构。如果未来要求后台维护多语言内容，则需要另行设计数据库字段、后台编辑入口和接口返回结构。
