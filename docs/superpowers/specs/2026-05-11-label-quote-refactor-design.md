# 标签不干胶报价参数重构设计

## 背景

本项目已有产品、报价模板、材料、工艺、报价规则、报价快照和前台在线报价流程。目标站点 sd2000 的标签/不干胶模块提供了更完整的产品信息与下单前参数体系，但用户已确认不直接复刻对方价格规则，也不要求接入真实下单付款权限链路。

本次重构在 `D:\study\Web\Dflc\yinshua\.worktrees\figma-homepage-sync` worktree 下进行。主仓库仅作为参考，不直接修改。

## 目标

保留现有后端报价公式和规则体系，引入标签/不干胶业务参数，让客户能按接近 sd2000 的产品信息完成报价前配置、文件与交付要求填写，并把这些参数纳入规则匹配、附加费、报价快照和后台复核。

## 非目标

- 不复制 sd2000 的价格、折扣、会员权益、优惠券或起步价数据。
- 不实现真实下单、付款、订单确认、售后、重下单闭环。
- 不依赖用户登录 sd2000 后的私有接口响应。
- 不把报价核心公式迁移到前端。

## 范围

### 前台报价体验

报价页从单页硬编码表单重构为四段式流程：

1. 产品与基础规格：产品、报价模板、宽高、数量、款数、形状。
2. 材料与印刷工艺：材料、胶型、使用环境、印刷颜色、覆膜/表面处理、模切、UV、烫金、打样、加急。
3. 卷装与交付要求：卷装/张装/单张裁切/折页，出标方向，卷芯内径，每卷数量，包装方式，期望交期，收货区域。
4. 文件与备注：是否已有设计文件、文件链接、是否需要设计服务、是否需要样稿确认、补充说明。

结果区展示最终报价、单价、成本拆分、附加费，并补充展示新引入的关键参数摘要，方便客户和后台客服复核。

### 后端报价模型

现有 `CreateQuoteDto` 继续作为报价入口，但需要扩展和整理参数：

- `styleCount`：款数。用于快照、规则条件和潜在附加费。
- `adhesiveType`：胶型，例如永久胶、可移胶、强粘胶、冷冻胶、耐高温胶。
- `usageEnvironment`：使用环境说明，例如冷冻、户外、防水、耐油。
- `deliveryForm`：卷装、张装、单张裁切、折页。
- `labelingMethod`：手工贴标、自动贴标、半自动贴标。
- `rollDirection`：上出、下出、左出、右出、内卷、外卷。
- `rollCoreMm`：卷芯内径。
- `piecesPerRoll`：每卷数量。
- `surfaceFinish`：哑膜、亮膜、哑油、光油、防刮、防水、白墨打底。
- `colorMode`：四色、单黑、专色、四色+白墨、可变数据/条码。
- `hasDesignFile`、`designFileUrl`、`needDesignService`、`needSampleApproval`：文件与设计复核信息。
- `packagingMethod`、`expectedDeliveryDate`、`shippingRegionCode`、`quoteRemark`：交付与备注。

新增参数进入 `snapshot.input`，历史报价必须保持生成当时的参数和规则快照。

### 报价规则

报价公式保持现状：

`最终报价 = max((材料 + 印刷 + 工艺 + 附加费) x 利润系数 x 会员系数, 最低报价)`

新参数以两种方式影响结果：

1. 规则命中条件：后台可按胶型、交付形式、颜色模式、表面处理、款数、卷装参数等匹配不同规则。
2. 附加费：现有白墨、可变数据、防护表面处理、分卷、单张裁切、折页、加急逻辑继续保留并扩展字段来源。

不引入 sd2000 的私有算法。若未来拿到合法授权的价格数据，可作为独立规则配置导入，不改变本次设计边界。

### 后台管理

后台报价规则页需要补充新条件字段和附加费配置项。后台报价详情需要展示新参数，尤其是文件、卷装、使用环境和交付要求。

产品模板管理不再只维护材料、工艺、印刷方式、形状。应支持模板声明可用参数项与默认值，前台据此渲染，避免继续硬编码。

## 架构

### 参数配置层

新增报价参数配置概念，建议先以代码常量或数据库 JSON 字段承载，后续再做完整后台配置 UI。

参数配置包含：

- 字段名、标签、控件类型、默认值。
- 可选项列表。
- 是否必填。
- 显示条件，例如只有交付形式为卷装时显示出标方向、卷芯、每卷数量。
- 参与规则匹配的字段标记。

### 前端组件

前台报价页拆分为：

- 产品选择组件：负责产品、模板切换。
- 报价参数表单组件：按参数配置渲染基础、工艺、卷装、文件交付字段。
- 报价操作组件：计算、保存、状态提示。
- 报价结果组件：金额拆分与参数摘要。

这样可以先在 React 中完成配置驱动渲染，未来接后端配置接口时不重写页面结构。

### 后端服务

后端保持现有服务边界：

- DTO 负责校验新参数。
- Validator 负责校验模板限制、数值范围、条件字段，例如卷装时每卷数量必须大于 0。
- Rule matcher 支持新条件字段。
- Calc service 保留核心公式，扩展附加费计算。
- Snapshot service 持久化完整输入、规则与结果。

## 数据流

1. 前端加载产品、模板和参数配置。
2. 用户选择产品与模板，表单生成默认报价输入。
3. 用户填写规格、工艺、卷装、文件与交付要求。
4. 前端提交 `POST /api/quotes/calculate`。
5. 后端校验输入并匹配当前规则。
6. 后端按现有公式计算价格和附加费。
7. 后端返回报价结果与输入快照摘要。
8. 用户保存报价时，后端保存报价单和完整快照。

## 错误处理

- 前端对必填字段、数字范围、卷装条件字段做即时提示。
- 后端仍作为权威校验源，返回明确中文错误。
- 计算失败时保留用户输入，不清空表单。
- 保存报价失败不影响当前已计算结果。
- 文件链接只是复核信息，不做真实上传校验。

## 测试策略

### 后端

- DTO/validator：验证新增字段、条件必填、范围限制。
- Rule matcher：验证新参数能命中不同规则。
- Calc service：验证白墨、可变数据、防护表面处理、分卷、单张裁切、折页、加急附加费。
- Quote service：验证保存报价时快照包含新参数。

### 前端

- 默认值生成：切换产品/模板后新参数正确初始化。
- 动态字段：卷装时显示出标方向、卷芯、每卷数量；非卷装时隐藏但保留可控默认。
- 提交 payload：新参数随计算与保存请求发送。
- 结果展示：金额和参数摘要不乱码、不溢出。

## 迁移与兼容

现有报价请求继续兼容。新增字段均可选，旧历史报价快照不需要补数据。已有数据库表可先利用 JSON 快照保存新增参数；如果后续要按字段检索，再增加结构化列。
